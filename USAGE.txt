Maritime VTS backend

Install the packages in requirements.txt in Python 3.12.

Set OPENAI_API_KEY, OPENAI_BASE_URL and OPENAI_MODEL for an OpenAI-compatible chat model with tool calling. Set OPENAI_EMBEDDING_MODEL to a model supported by the same endpoint. Set VTS_DB_HOST, VTS_DB_PORT, VTS_DB_USER, VTS_DB_PASSWORD and VTS_DB_NAME for MySQL 8. Use a database account with SELECT privileges only. llm-vts/.env.example lists the configuration variables.

Run a question:

python -m vtsllm "Which vessels are in the strait?"

From the project root, Python callers can use:

from vtsllm.agent import run_agent
answer, trace = run_agent([{"role": "user", "content": "Which vessels are in the strait?"}])

The JSON output contains the answer and the tool call trace. The model can inspect the schema, consult the historical maritime schema reference, find entities, search knowledge, validate SQL and perform vessel, traffic flow and collision queries. The reference may differ from the connected database and does not populate the knowledge collection. Each SQL statement is checked with EXPLAIN before execution. Queries return at most 100 rows and indicate truncation. Query results include the SQL executed with a row limit. MySQL session variables are rejected; use explicit values or subqueries.

If an agent call fails, the original exception includes the completed tool trace in its notes. The trace can contain database results.

Malformed tool arguments with a call ID are returned to the model as a tool error so it can retry. Repeated attempts are bounded by the graph recursion limit; SQL execution remains subject to validation.

Entity search matches without regard to letter case, returns up to 20 matches per table field and identifies fields with additional matches.

To load the bundled shapefiles, install llm-vts/data/requirements.txt in addition to the root requirements, configure llm-vts/config.yaml, and run:

python llm-vts/data/load_shp_data.py llm-vts/data/general/Strait.shp

The loader creates and inserts into the configured MySQL database. Without a path argument, it loads the bundled Singapore port shapefile.

The knowledge collection starts empty. Import text, Markdown or text-based PDF documents:

python -m vtsllm.knowledge /path/to/rules.pdf /path/to/definitions.txt

VTS_KNOWLEDGE_DIR selects the persistent Chroma directory. Document import and search use the configured embedding endpoint. Keep the embedding model consistent for an existing collection. Reimporting a file replaces its previous chunks. Search returns up to four nearest chunks with their source and vector distance; next_offset allows retrieval of further matches. Each search ranks all indexed chunks and retains the current result pages in memory, so time and memory use grow with collection size. Search does not apply a calibrated relevance threshold. An empty collection does not supply maritime rules.

Run the VTS-SQL evaluation after configuring the model and database:

python maritime-qa/ours.py --split dev --output ours.csv

The evaluation measures SQL result comparison only; it does not assess the final answer or autonomous tool selection. It compares all returned column values and row multiplicities, and checks row order when the reference query has a top-level ORDER BY. Order differences with the same rows are inconclusive because the reference order may contain ties. Empty results, truncated results and query failures are inconclusive. The reference queries use the same read-only database tool and row limit. The dataset's @CNOW reference resolves to the latest ship_ais timestamp. Use a fixed database snapshot for reproducible comparisons.

Each completed evaluation is written immediately. The tool_trace column contains the tool calls, arguments, results and statuses as JSON, including any data returned by the database. If execution fails, the CSV retains completed rows and the error is reported. Choose a new output path for each run; an existing file is not overwritten.

The bundled test_dataset.json contains 38 examples in each of train and dev; all 38 examples are identical across the two splits. Results on dev do not measure generalization to unseen examples.

Run the isolated tests:

python -m unittest discover -s llm-vts/tests -v

README.md describes the historical RAGFlow and Flask version. AIS records and the original knowledge collection are not included in this repository.
